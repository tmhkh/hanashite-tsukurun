# Requirements 11-17 (v2): Layout variations, animations, custom theme, StructureVisualizer, StepGuide, QuestionRationale, CompletionFeedback

Seven features added to the child-friendly presentation builder. The backend prompt now instructs Claude to produce layout-varied Marp markdown (lead/two-column/centered) with bold/emoji/blockquote decoration, a `hanashite-pop` theme reference in frontmatter, and a `completion_feedback` field. The frontend replaces ProgressBar with StructureVisualizer, shows StepGuide after each step completion, renders QuestionRationale hints below the AI bubble, applies CSS enter-animations on the slide viewer, and displays CompletionFeedback on the finish screen. The `completion_feedback` field flows from Lambda through App state to FinishScreen, with server-side enforcement of empty values for non-step-3 responses.

## Theme file as dead CSS

`src/styles/marp-themes/hanashite-pop.css` defines `@theme hanashite-pop` with section classes (`.lead`, `.two-column`, `.centered`), heading colors, blockquote styling, and font declarations. None of this is imported by any component or passed to a Marp rendering pipeline. The MarpSlideViewer uses its own inline glassmorphism styles and a custom parser.

When a user copies the generated markdown via the "スライドを コピー" button and pastes it into an external Marp environment (VS Code, Marp CLI), they would need this theme file registered separately. The current implementation doesn't bundle or serve it alongside the markdown copy — external Marp will fall back to the default theme, losing the layout class styling.

## Reduced-motion interaction with animation initial states

```css
.slide-text { animation: slideUp 0.5s ease-out 0.3s forwards; opacity: 0; }

@media (prefers-reduced-motion: reduce) {
  .slide-text { animation: none; opacity: 1; transform: none; }
}
```

The `.slide-text` rule sets `opacity: 0` outside the animation. The `prefers-reduced-motion` block overrides this to `opacity: 1`. Both selectors have equal specificity (single class), so source order determines the winner — the media query block appears later and should win when the condition matches. The reduced-motion path is untested in the automated suite because JSDOM doesn't evaluate media queries.
