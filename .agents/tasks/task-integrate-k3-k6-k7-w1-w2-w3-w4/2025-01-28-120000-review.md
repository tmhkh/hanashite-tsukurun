## 要件7.1 と要件13.4 のテーマ指定矛盾

要件7.1（line 152 of requirements.md）は Marp フロントマターの形式を `theme: default` と規定している。しかし新規追加の要件13.4 は Slide_Exporter が `theme: hanashite-pop` を指定すべきと明記している。design.md 側はプロンプト指示・モックデータともに `hanashite-pop` に統一済みだが、要件7.1 だけが旧仕様のままで矛盾が残る。

要件7.1 は `paginate: true` のみをフロントマターとして規定しているが、design.md の Slide_Exporter プロンプト指示は `header` / `footer` ディレクティブも含んでおり、要件13.5 がこれを要求している。要件7.1 を更新して新しいフロントマター構造を反映させるか、要件13 が要件7 を上書きする旨を明示する必要がある。

## Progress_Bar と Structure_Visualizer の並存

要件6.6 は「THE Progress_Bar SHALL Step 1〜3 の各状態を...識別可能な形で表示し」と現在形で規定している。一方、要件14.1 は「THE App SHALL メイン画面において、Progress_Bar の代わりに Structure_Visualizer を表示する」と宣言しており、両者は矛盾する。

用語集の Structure_Visualizer 定義にも「Progress_Barの拡張/代替」と記載されており、設計意図は置換であることが明確。にもかかわらず要件6.6 が生存しているため、実装者が「Progress_Bar も並行して存在する」と誤読するリスクがある。要件6.6 を削除するか、Structure_Visualizer への参照に書き換えるべき。

## アニメーションのアクセシビリティ受入基準

design.md の Slide_Animation CSS 仕様セクションは制約事項として `prefers-reduced-motion: reduce` メディアクエリの尊重を明記している。これは WCAG 2.1 SC 2.3.3 に対応する重要な要件だが、requirements.md の要件12（アニメーション付きスライド出力）の受入基準1〜6にはこの制約に相当する項目がない。

design.md にだけ記載があり requirements.md に対応がないと、テスト設計時に見落とされる可能性がある。要件12 に「THE App SHALL `prefers-reduced-motion: reduce` メディアクエリが有効な環境において、すべての Slide_Animation を無効化またはデュレーション0に設定する」相当の受入基準を追加すべき。

## Two-column レイアウトの設計ギャップ

要件11.2 はページ2に2カラムレイアウトを適用すると規定し、design.md のプロンプト指示にも「2カラムレイアウト。左カラムに slide_text 本文、右カラムに image_keyword アイコン/イラスト配置」と書かれている。しかし Marp には標準の `two-column` ディレクティブが存在しない。

design.md の `hanashite-pop.css` サンプルは `section.lead` と `section.centered` のスタイルを定義しているが、2カラム用のクラス（`section.two-column` や CSS Grid/Flexbox 定義）が欠落している。ページ1は `<!-- _class: lead -->`、ページ3は `<!-- _class: centered -->` で実現方法が明確だが、ページ2 だけ具体的な実装手段が未定義。

実現手段の選択肢は: (a) `hanashite-pop.css` に `.two-column` クラスと CSS Grid 定義を追加する、(b) Marp の `<!-- _class: -->` と `<div>` による手動レイアウト指定をプロンプト指示に含める、(c) Marp の Built-in columns 記法（`---\n\n<style scoped>...`）を使う。いずれにしても設計書上で手段を明示する必要がある。

## 要件4 のレスポンスフィールド定義の未更新

要件4.4 は Slide_API のレスポンスに含まれるべきフィールドを列挙しているが、その列挙に `completion_feedback` が含まれていない。要件17.5 が `current_step` 3 のレスポンスに `completion_feedback` フィールドを含めることを規定しているため、要件4.4 のフィールド一覧を更新して整合性を確保すべき。
